# 首启引导的真动作验收

`verification/ui/` 的 driver 只有 `simctl`，**没有点击能力**（见
`docs/research/verified-behaviour.md` 第 8 条），而首启引导的价值全在交互上：能不能
翻页、能不能跳过、看完之后还会不会再出现。所以这一层用 Maestro 真点。

```sh
bash verification/onboarding/run.sh          # 默认英文，冷启动清钥匙串
```

## 它断言什么

| 断言                                      | 为什么值得一条                                       |
| ----------------------------------------- | ---------------------------------------------------- |
| 首屏是引导第 1 页，且"跳过"在             | 冷启动路径没坏；出口存在（没有出口的引导会逼人乱点） |
| 横划 → 第 2 页文案                        | 分页真的翻得动，不是三页叠在一起                     |
| 横划 → 第 3 页文案                        | 同上                                                 |
| 第 3 页"跳过"收起、主按钮变 "Get started" | 最后一页不该自相矛盾                                 |
| 点 "Get started" → 登录页                 | 引导的终点是登录，不是死路                           |
| 再次冷启动 → 直接登录页，引导不再出现     | "看过"的记忆真的写下去了（只出现一次）               |

证据落在 `out/<时间戳>/`：每一屏一张截图（`--debug-output` 指定）。

## 前置

1. 模拟器：`Memoh * Verify` 池子里的一台（默认取第一台在跑的），上面装好当前 Debug App。
2. Metro 在 8097 上跑（`pnpm exec expo start --dev-client --host lan --port 8097`）。
3. Maestro 在 PATH 里（`$HOME/.maestro/bin`）。
4. 不需要登录，也不需要隧道——引导不联网。

脚本会**临时移开验收种子**（`Documents/memoh-verify-seed.json`）并在结束时放回去：
有种子时 App 会按种子走、跳过引导，那就看不到这一屏了。
